# Rive animations

Every animated stickman scene on the site is a Rive file in `public/rive/`. None of them
were drawn in the Rive editor. Each `.riv` is **generated by a Node script** in
`scripts/rive/`, and the generated binary is committed. To change an animation you edit
the script and rebuild; never hand-edit a `.riv`.

## How to change an animation

1. Find the file in the catalogue below and open its generator in `scripts/rive/`.
2. Edit shapes, poses or keyframes.
3. From the repo root, run its script, for example `npm run rive:cta`. It overwrites
   `public/rive/cta.riv` and prints the file size. Any writer warnings are printed too.
4. Reload the page in `npm run dev` and check it.
5. If you changed timing, update the page code that is synced to it (see
   [Syncing pages to animations](#syncing-pages-to-animations)).
6. Commit the script and the regenerated `.riv` together.

The scripts write through `createRiv` from `rive-mcp-server/dist/rivWriter.js` (a
devDependency, so run `npm install` first). The runtime `public/rive/rive.wasm` is copied
from `@rive-app/canvas` by `postinstall` and is gitignored.

## How the page plays a file

Pages never use `@rive-app/react-canvas` directly. They render
`components/motion/RiveScene.tsx`:

- Props: `src` (e.g. `"/rive/cta.riv"`), `artboard`, and either `animation` (a linear
  animation to autoplay) or `stateMachine`. Plus `inputs` (number/bool state machine
  inputs, synced when the object changes), `triggers`, `onAdvance(seconds)`, `onLoop()`,
  `frameClassName` (the canvas has no height of its own, so give it an aspect ratio that
  matches the artboard) and a required `fallback`.
- The fallback renders until the scene is near the viewport, the file exists (a `HEAD`
  check) and it loads. It also renders **always under `prefers-reduced-motion`** and if
  the file fails to load. `fallback={null}` is fine for decorative scenes.
- `RivePlayer.tsx` is loaded with `next/dynamic` (`ssr: false`) so the runtime stays out
  of the main bundle. It uses `Fit.Contain`, and pauses the animation while off screen.
- Memoise `inputs` (`React.useMemo`). A new object each render re-applies the inputs.
- `RiveScene` also supports `scrollProgress`, which drives a number input named
  `progress`. No current file has that input.

## Conventions

- **60 fps, frames everywhere.** Keyframes are `[frame, value, easing]`. Easings used:
  `hold`, `linear`, `ease-in`, `ease-out`, `ease-in-out`, `ease-out-back`.
- Colours come from `kit.mjs`: `WHITE`, `AMBER` `#FBBF24`, `BLUE` `#1E40AF`, `DEEP`
  `#1E3A8A`, `NIGHT` `#0E1424`. Light section scenes use `line: BLUE, paper: "#EEF1F5"`.
- Coordinates: artboard units, y down. A figure's feet sit at its group origin.
- Artboard backgrounds are transparent unless the scene draws its own.
- Names in the page code (file, artboard, state machine, input) are case sensitive.

### `kit.mjs` API

`makeKit(G, { line, paper })` returns a kit. `G` is the ground line y; `line` is the
stroke colour, `paper` the fill behind heads and bodies.

| Function                                   | Does                                                                                                                                                                                                       |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `figure(id, x, { glasses, fat, y, halo })` | Adds a stick figure at `x`. Joint groups are `${id}_body`, `${id}_uaL/R` (upper arm), `_faL/R` (forearm), `_thL/R` (thigh), `_shL/R` (shin). `fat` gives a pear body; `halo` draws a thick outline behind. |
| `pose(id, frame, nameOrObject, easing)`    | Keys every joint rotation (degrees, 0 = hanging straight down) plus `lean`. Named poses: `stand`, `sketch`, `sketch2`, `reachUp`, `press`, `ears`, `type`, `point`, `cheer`, `fiveL`, `fiveR`.             |
| `reach(id, side, x, y)`                    | Two bone IK. Returns `{ uaL, faL }` (or R) that put that hand on `(x, y)` in the figure's own coordinates. Spread it into a pose object.                                                                   |
| `walk(id, f0, f1, x0, x1)`                 | Moves the figure from `x0` to `x1` over frames `f0` to `f1` with a 12 frame step cycle and bob.                                                                                                            |
| `key(target, prop, frames)`                | Low level: append keyframes to any group or shape (`x`, `y`, `rotation`, `scaleX`, `scaleY`, `opacity`, `fillColor`...).                                                                                   |
| `group`, `line`, `shapes`, `groups`        | Add groups and polylines, or push raw shapes.                                                                                                                                                              |
| `tracksOut()` / `takeTracks()`             | Collect the keyed tracks. `takeTracks` also clears them, for files with several animations.                                                                                                                |

### Pitfalls we have hit

- **Easing applies to the arrival at a keyframe**, not the departure. A value moves from
  the previous keyframe to this one using this keyframe's easing. To hold still and then
  move, add a `hold` keyframe at the start of the move, otherwise it drifts the whole time
  between keyframes.
- **Group opacity does not hide children** in this writer. To hide something, key
  `scaleX`/`scaleY` to 0 (see `pop` in `agents.mjs`, and the chore in `strike.mjs`).
  Opacity on a single shape works.
- **Text draws above all shapes.** A shape that has to cover text (the painted cover in
  `portfolio.mjs`) needs `z: 2500`.
- **Mirrored figures need flipped reach x.** A figure turned with `scaleX: -1` (e.g. the
  dev in `transform.mjs`) has its own x axis flipped, so pass `-x` to `reach`.
- **framer-motion owns `transform`.** On a `motion.*` element, Tailwind transform classes
  such as `-translate-x-1/2` are overwritten. Put the Tailwind positioning on a static
  wrapper `span` and animate the inner element (see the bullet hole in `TeamElevator.tsx`).
- Upper arms are clamped to ±145° in `pose` so they never swing through the head.
- Keep each file small; one file with several artboards beats several files.
